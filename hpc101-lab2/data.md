### R27b (仅树形归约, 8线程) — ❌ 失败回退
假设: 树形归约本身减少归约访存量, 8 线程下应有小幅改善。
结果: S4 1.504→1.863s (**-19%**)。树形归约反而更慢: 后续合并趟 (4→2→1 对) 线程
利用率递减, 最后一趟仅 1 核处理 524K 元素 (8x 慢于顺序的 8 核并行)。大 ystride
下顺序归约的均匀 8 路并行优于树形。已 git checkout 回退到 R25。
| 场景 | R25 (s) | R27b (s) | 变化 |
|------|---------|----------|------|
| S3 | 0.100063 | 0.0988951 | +1.2% (噪声, strided 路径未变) |
| S4 | 1.50437 | 1.8629 | -19% ❌ |

**关键教训:** S4 归约 (顺序, 8 线程) 已近最优; 树形归约因后续趟线程利用率递减反而更慢。
S4 受 DRAM 带宽硬限制 (98MB 权重 > 47MB L3, 8 线程已饱和), 难以进一步提升。

结果: S3 持续 ~2% 回退 (R29 中位 0.1054s vs R25 同条件中位 0.1031s)。

### R32 (LPT 专家调度 + nowait 尾部归约) — ✅ 保留

**假设/VTune (R30, S3, 5000 iter 热点):** S3 头号开销为 libgomp 自旋 ~1.13s CPU (~14%),
源于 16 专家/8 线程 schedule(dynamic) 的负载不均 (Poisson token 数, 尾延迟大)。
专家循环体 1.156s(含自旋) | amx_matmul_packed(Gate+Up+Down分离) 0.557s | __memset 0.340s | compute_shared 0.132s。
**改动 (仅 OpenMP 并行方向):**
1. compute_routed_experts_parallel 入口按 g_expert_token_count 降序排列专家索引 (LPT,
   longest-processing-time-first), schedule(dynamic) 先抓最重专家, 每线程自然配成 重+轻。
2. shared_expert 末尾 dequant omp for 加 nowait (区域末尾, 冗余屏障)。
3. S3 routed 归约(else 分支) omp for 加 nowait (idx 互斥, 安全)。
正确性: 专家求和顺序变化 <1e-7 (dynamic 本就非确定), 远低于 2e-3 阈值。

### R33 (M=1 AVX-512 VNNI 精确 GEMV) — ✅ 保留

**优化假设:** S2 的主要热点是 `small_m_*_output_major` 中的 INT8→INT16 扩展与
`VPMADDWD`。对单行 GEMV 使用 `VPDPBUSD`，令 `a_u8=a_s8+128`，并在
`preprocess()` 预计算每个权重输出行的元素和，以
`dot(a_s8,w_s8)=dot(a_u8,w_s8)-128*sum(w_s8)` 精确修正，可减少转换指令并将
N 维展开从 4 扩大到 8。该路径仅在原有 small-M 分派且 `M=1` 时启用。

**测试条件:** `hpc submit -p lab2 -c 16`, 1000 iterations, `--benchmark`。

|------|----------------|--------|-------------|------|------|
| S1 | 0.0122503 | 0.0113767 | 4.45× | 2.34e-05 | 路径未触及，波动 |
| S2 | 0.139622 | 0.110268 / 0.113382 / 0.122867 | 5.43×（中位） | 7.36e-06 | +13.2% vs R32 历史中位 |
| S3 | 0.122390 | 0.102789 | 64.35× | 3.42e-05 | 路径未触及，波动 |
| S4 | 1.534140 | 1.487380 | 154.46× | 1.05e-05 | 路径未触及，波动 |

**结论:** S2 三次测量均快于 R32 历史中位 0.13069s，且输出逐项量化结果保持一致；
保留该版本。S1 仍走 AMX 路径，下一轮单独研究 S1 专用 kernel。

### R34 (VNNI 平台 M=1 无条件走单行 kernel) — ✅ 保留

**优化假设:** 让 ZMM 的 16 个 INT32 lane 直接对应 16 个输出通道，广播 4 个输入

4-byte 输入广播及更深循环也抵消了水平归约节省。正确性通过，但性能明显下降，已回退 R34。

## R87: S3 lazy memset elimination (2026-07-28) **[SUCCESS - NEW BEST]**

### 优化假设
`std::memset(y_acc, 0, 128KB)` 在 expert 计算前刷新 L1/L2 cache, 影响 weight 加载性能。用 lazy init (首次写入直接 store, 后续 accumulate) 替代, 保留 cache 状态。

### 设计
- 移除 `std::memset(y_acc, 0, ystride * sizeof(float))`
- 添加 `char token_init[MAX_NUM_TOKENS] = {0}` 跟踪每线程首次写入
- AVX-512 路径: if(token_init[t]) accumulate else direct store + mark
- expert loop 后扫描未触及 token, 补零, 再 barrier
- `#pragma omp barrier` 确保 zeroing 完成后再 reduction (修复竞态)

### 首次实现 bug (R87a)
遗漏 `#pragma omp barrier` 导致 2/8 次正确性失败 (RMSE 0.00269, 略超 0.002 阈值)。fast thread 在 slow thread zeroing 未完成时开始 reduction, 读取到 uninitialized y_acc。修复后 10/10 通过。

### R192: move large-E runtime allocation/first-touch into preprocess [FAILED, reverted]

- Hypothesis: OJ does not warm the optimized path, so S4's first timed call pays OpenMP worker startup, per-thread scratch allocation, AMX permission requests, the 16 MiB `y_acc` allocation and page first-touch. With only 10 iterations this cold cost is large.
- Change: for `E>=64`, `preprocess()` created an 8-thread OpenMP team, requested per-thread AMX permission, allocated each thread's maximum-size `ExpertScratch`, allocated the maximum S4 `y_acc` pool, and first-touched every accumulation slice.
- Correctness: S1-S4 all passed.
- Three-run median OJ speedups, R179 -> R192: S1 21.324 -> 21.719; S2 15.805 -> 16.134; S3 61.721 -> 61.202; S4 132.048 -> 120.775.
- S4 median optimized time regressed from 17.3035 ms/10 iterations to 18.9403 ms/10 iterations. One candidate run reached 15.1714 ms, but the other two were 18.9403/19.0666 ms, so the gain was not stable.
- Diagnosis: the prewarm was too aggressive. Touching roughly 72 MiB of maximum per-thread scratch plus 16 MiB of `y_acc` at the end of preprocess displaced useful packed/router data and enlarged the active memory footprint. Moving cold work out of the timer is still plausible, but it must happen before weight packing and should be isolated into smaller components.
- Decision: reverted to R179. Next: pre-touch only the S4 accumulation pool before weight packing, leaving thread scratch demand-sized.

### R193: pre-touch only S4 y_acc before weight packing [FAILED, reverted]

- Correctness: S1-S4 all passed.
